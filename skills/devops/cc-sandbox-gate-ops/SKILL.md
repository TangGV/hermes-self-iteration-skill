# CC Sandbox 门禁出网排障

- 先读目标环境最新的检查记录，区分普通出口、TUN、官网看到的出口 IP 三项。官网检查需收到 `cdn-cgi/trace` 的 `ip=` 并核对实际出口；启动后立即拿到 HTTP 200 不等于官网必过项通过。
- 用同镜像、同节点、同桥接运行真实探针与判分逻辑。临时容器必须使用独立名称、临时密钥目录，不挂账号卷、不写生产检查结果。临时数据和探针清理后再交付。
- TUN 启动即拨不上游：观察 `IPReversePathFilter` 计数。严格反向路径检查下，上游回包的反向查询不带代理 UID，不能只用 UID 选择路由。只针对上游 IPv4 安装主表 `/32` 路由，优先级低于 DNS 防泄漏规则、高于 TUN 默认规则；保留 `rp_filter`，仅允许代理进程访问上游 IP 和端口。
- TUN 初始通、数秒后超时：对照同桥接无 TUN 的探针。如果宿主外网口收到匹配的 SYN-ACK，但 Docker 网桥未转入，查网关 ARP 邻居续期。只把网关 `/32` 的查询指向主表的直连路由，别给网关新增 `OUTPUT` 放行，也不改公网默认路由。
- 对比原代码与候选修复的真实检查输出；确认官网看到的 IP 与出口匹配，杀掉代理后 DNS 和公网直连仍被拦截。未明确授权生产重启时，修复只暂存，不覆盖线上文件、改账号、切节点或启动正式环境。
